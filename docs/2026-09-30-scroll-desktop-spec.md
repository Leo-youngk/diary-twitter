# 首页滚动修复与桌面随想布局

## 目标与范围

用户已明确授权修复 iPhone 首页快速上下滑动时的停顿。电脑主要用于浏览、写短随想；2026-09-30 用户回复「按这个三栏方案做」，确认本文及原型的桌面方案，授权实现、验证、提交、推送并部署到现有 Cloudflare 站点。

本次不改数据模型、同步码或外部投递约定，不接入新服务、不更换框架。沿用 React / Vite / Stackflow / TinyBase 和现有主题、字体。手机保留既有导航、全屏写作、详情与返回方式。

## 调查与方案依据

- 已读现有依赖和滚动历史：`7f46349` 移除虚拟列表，避免 iOS 惯性滚动被估计高度修正打断。本次继续采用原生列表，不恢复旧虚拟列表。
- 首页每次追加 40 条，隔离 Chrome、390×844、4 倍 CPU 降速下已有约 240ms 主线程长任务的证据。`PostText` 每条同步测量并更新状态；全局非被动触摸监听还在滑动期间读取布局。
- [Safari 16 的 Overscroll Behavior](https://webkit.org/blog/13152/webkit-features-in-safari-16-0/) 已支持边界控制；当前代码“iOS 完全不支持”的注释过时。支持时使用 CSS 和浏览器原生滚动，仅不支持的浏览器保留必要的兼容处理。不在普通滑动期间改写 `scrollTop`。
- 调查 [Mastodon](https://github.com/mastodon/mastodon) 的 `features/ui/index.jsx` 及许可证：React UI 按窗口布局选择单列/多列，并为多列视图组织上下文；AGPL-3.0。仅参考交互，不复制代码、不引入 Mastodon 服务。项目仍在维护（检查日为 2026-09-30）。
- 新数据插入验收发现重复补偿：Chrome 自动保持阅读位置后，旧代码又累加新行高度，实际偏移约 331px。[Safari 27 新增 Scroll Anchoring](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)；支持 `overflow-anchor` 时交给浏览器，不支持时仅对插入在阅读位置上方的行补偿，包括其展开按钮产生的高度变化。

## 滚动修复

缩小追加批次，提前分批渲染，避免一次 40 条挤占主线程；集中处理文字是否折叠的测量，先读取再更新；减少滑动回调中的重复布局读取。保留长文展开、字号切换、图片比例和新增帖子时的阅读位置。

验收：

1. 320 条长短混合测试随想 → 快速向下连续滚过分页边界再向上 → 没有缺行、重复行或程序性滚动回跳；最终可到列表底部。
2. 同一 Chrome、390×844、4 倍 CPU 降速条件 → 比较分页追加任务 → 大于 100ms 的追加阻塞消除或有明确剩余原因，最慢追加任务明显低于基线约 240ms。该指标是实验室条件，不代表 iPhone 真机。
3. 长文字、字体/字号和窗口宽度改变 → 展开入口正确、内容不被永久截断；正常短帖不显示多余按钮。
4. 切换标签、打开详情/写帖再返回 → 时间线阅读位置保持；图片加载和新增数据不造成无理由回跳。
5. iPhone 真机尚无法直接操作。部署后需用户快速上下滑动反馈；浏览器模拟不得报告成真机已通过。

## 已确认的桌面方案

原型：[desktop-preview.html](desktop-preview.html)，内容全部为明确标记的样例。

宽屏（默认 ≥1280px）：左侧固定导航约 208px，中间时间线随窗口约 600–760px，右侧约 360px，整体最大宽度 1360px。

- 默认右侧“写一条随想”：真实发帖、图片、X 开关、长度提示和草稿保存；不需要把时间线切换成整个写作页。
- 点中间的帖子 → 右侧显示正文和追加 → 中间阅读位置不变。
- 右侧可切回写新随想，未发布草稿保留；编辑原帖、追加仍复用现有数据动作与 X 约定。
- 电脑标题、导航保持可见，不随滚轮滑出屏幕；帖子宽度与密度适合短随想，使用原有字体及主题。
- 1024–1279px 采用导航 + 更宽内容区；详情与写作沿用独立页面，确保操作可用。小于 768px 沿用手机布局。
- 设置、目标、日历、统计及原有资料/收藏入口保留，不新增推荐内容、搜索或管理功能。

验收：1440×1000 和 1920×1080 能一边浏览一边写帖，点详情保留时间线位置，关闭/切回不丢草稿；1024×768 与 390×844 无横向溢出；真实本地双浏览器短帖/收藏/追加同步通过；X 测试保持关闭，不向真实账号发样例。

未决项：iPhone 真机的惯性滚动效果。用户已确认三栏方案，无其他产品决策待定。

## 实现与验收记录

- 原生列表首次 16 行，每批 4 行，提前 2200px 加载；追加使用 React transition。共享 ResizeObserver 批量读取正文尺寸；每分钟只更新时间标签。现代浏览器移除 document 的非被动 `touchmove` 边界处理，保留必要的旧版兼容与边缘返回保护。
- 桌面复用手机的真实 Composer、PostDetail 和数据动作；新帖草稿表单在右侧切换时保持挂载。未保存的编辑、追加在离开前确认；发帖后清空内容与图片。设置/资料返回复用已有首页，避免重新建立时间线。
- 实际 Chrome：1440×1000、1920×1080 三栏；1024×768 双栏；390×844 手机。无横向溢出，桌面标题在滚动时保持可见。
- 本地 Cloudflare Worker + 独立浏览器：桌面图片发帖、详情追加、编辑保存、取消离开编辑/追加、草稿文字与图片保留均通过；手机全屏发帖、详情追加、收藏也通过，两端接收对应数据，X 投递数为 0。
- 新增长帖时，同一阅读行的屏幕位置偏差：原生锚定约 0.75px；禁用原生锚定后的兼容路径约 0.25px。兼容路径是 Chrome 内模拟，不是 Safari 真机。
- 390×844、4 倍 CPU 降速，320 行快下/快上检查通过：完整到达底部并回到顶部，普通滚动没有程序性 `scrollTop` 写入；长文展开/收起、宽度改变和字号改变后折叠入口正确。性能结果和最终检查见交付记录。
- 测量逻辑新增 2 项有效回归测试：先读全部段落再更新，以及已移除段落不再读取/更新。完整 58 项测试、类型检查与 lint 通过；发布前执行最终生产构建。
