# PC 与移动端同步修复（2026-10-09）

## 原因与实现

正式站使用 D1、HTTP 增量同步和 TinyBase CRDT。以远端 `master` 的 `fe163aa` 为基础修复，保留已有的 X、Substack、Threads、分析页和发布进度。初始工作目录停留在旧 WebSocket 分支；旧版探索没有成功部署，不作为本次上线版本。D1 接受新数据后不能回退到旧 DO 写入器，见 [D1 迁移记录](2026-10-02-cloudflare-d1.md)。

- 正常空闲时每 30 秒才拉取其他设备更新，只有等待外部发布结果时缩短到 3 秒。改为前台每 2 秒增量检查，本机编辑仍在 150 ms 后提交；后台暂停定时检查。
- 返回前台或重新联网时，原实现只标记“稍后再同步”，继续等待已经卡住的请求。现在取消旧请求、使其响应失效，立即重新同步；覆盖 `visibilitychange`、可见窗口的 `focus`、联网和 BFCache 恢复。
- 原请求超时只覆盖响应头，正文不完整可能永久占用同步。20 秒超时现在覆盖完整 JSON 正文，并保留未确认的本地改动以供重试。
- 图片上传的空队列检查会留下已完成的 Promise，阻止后续启动。把锁释放移到 `.finally()`，同一轮继续读取新加入的图片；失败保留队列，联网和成功同步后重试，单次 PUT 最多等待 30 秒。
- 设置新增“立即同步”，设备列表的本机状态使用真实连接状态；手动重试不会用提示消息假定成功。

复用现有 TinyBase `10.0.1`（MIT）和 D1 游标协议，没有增加依赖或修改数据库、数据迁移及发布接口。参考现有 [TinyBase 开源实现](https://github.com/tinyplex/tinybase) 和安装包中的 MergeableStore 实现。HTTP 请求中止、前台恢复、待确认记录缓存及图片重试由本项目实现。

空闲请求携带游标和空记录列表，不重复上传全量数据；缓存整理过的待确认记录，只有本机修改或收到远端记录才重新序列化。收到相同可见值但更新 CRDT 时钟的记录也会使缓存失效。仍按精确发送快照确认记录，保留同步过程中产生的编辑与离线冲突合并。既有 D1 测试继续验证空闲检查零数据库写入。

## 验证

- `npm run test`：27 个文件、260 项全部通过。新增回归覆盖 2 秒内收到远端修改、空闲不重新序列化、相同值的新时钟确认、正文卡住超时、短暂后台恢复，以及空队列后新增图片、网络失败重试、离线队列和上传途中新增图片。
- `npm run lint` 与包含 `tsc -b` 的生产构建通过。Windows 构建沿用 `scripts/cloudflare.mjs` 的非 ASCII 路径修复。
- 对隔离的本地 D1 应用 `migrations/0001_diary.sql`，使用独立 Chrome（1440×1000）与移动 WebKit（390×844）上下文连接真实本地服务。使用 DOM 和同步读取的 Store 状态等待结果，不把异步 predicate 返回的 Promise 当成完成。

| 本地场景 | 实测结果 |
| --- | --- |
| PC 界面保存 → 移动端显示 | 1937 ms |
| 移动端收藏 → PC 更新 | 449 ms |
| 一次 HTTP 失败后补同步 | 2366 ms |
| 断网后双向补同步 | 2186 ms |
| 后台遗留请求卡住，恢复前台后收到修改 | 394 ms |

编辑、追加、目标完成、设置按钮、新图片上传、新设备读取服务端持久化记录和测试记录删除均通过。两个视口横向溢出为 0，JavaScript 错误为 0，外部 X 测试发布为 0。上述耗时仅代表本地浏览器测试，不代表真机或线上网络延迟。

本地验证脚本与截图保存在 `output/playwright/device-sync/`，不纳入提交。正式站验收只登录、读取和触发同步，不创建测试日记。

## 发布与更新

使用 `npm run deploy`，沿用正式 D1 绑定及 `v2` Durable Object 迁移配置。脚本从已忽略的环境文件读取凭据，并删除构建目录中的 `.dev.vars`。

已打开的 PWA 需加载新版本：看到“有新版本，点击更新”时点击；也可关闭后重新打开。设置 → 设备可以核对本机版本。版本更新与记录同步分开处理，写作过程中不强制刷新页面。
